# VOYAGE V1 — 完整整合與驗收規格

## 開發原則
- 本分支為整合開發；正式 main 只有通過整體驗收後才更新。現有 main 中間版不得視為交付。
- 既有 localStorage `voyage-v02` 資料須相容，任何遷移前備份；不得無確認覆蓋或刪除行程。
- 手動規劃優先；AI 與路線建議僅提出可預覽變更，經使用者確認才加入。
- 沒有可信來源時，不得顯示假的即時班次、GPS 列車位置、匯率或 AI 推薦。
- iPhone Safari、窄螢幕、安全區、重開瀏覽器、網路失敗、無定位權限、空資料均須測試。

## 功能驗收矩陣
| ID | 模組 | 最低可驗收行為 |
|---|---|---|
| 01 | 旅行首頁 | 任意國家城市建立多趟旅行、日期、時區、倒數、天氣狀態、航班住宿摘要、歷史切換；亮色藍白及柔和夜景 |
| 02 | 行程 | 單日／橫向週檢視共用資料；活動分類、開始結束時間、費用、備註、連結、衝突警告、可編輯；交通作為正式事件 |
| 03 | 地圖 | 真實地圖圖磚、GPS 權限、當日站點編號、列表同步、Google/NAVER 各自連結與平台辨識；不得用直線冒充路線 |
| 04-A | 交通規劃 | 起終點、時間、方向、候車步行、站數、轉乘、人工時間；可寫入時間軸並開啟搭乘助手 |
| 04-B | 搭乘助手 | 多段轉乘步驟、站名雙語、方向、目前站、下一站、剩餘站；資料來源標籤；有官方追蹤才稱自動，否則明示手動 |
| 05 | AI 建議 | 來源可查、距離時間合宜、確認後新增、失敗時明確提示；未接服務不得冒充 |
| 06 | 匯入匯出 | JSON 備份與復原、TXT/CSV/ICS/筆記解析預覽、去重與附加匯入；絕不默默覆蓋 |
| 07 | 多人同步 | 真正雲端身分／邀請／權限／衝突處理／修改紀錄；純 localStorage 不算完成 |
| 08 | 費用 | 任意頁快速記帳、目的地幣別、匯率來源時間、手動覆寫、歷史匯率鎖定、分攤結算 |
| 09 | 翻譯 | App 內雙向翻譯、禮貌程度、回譯及語意警示、語音重播；API 未設定時明示不可用 |
| 10 | 航班住宿 | 時區、跨日、地址、入住退房、文件安全與導航 |
| 11 | 行李／歷史 | 分人勾選且彼此獨立、共用品責任、清單分類、願望清單、旅程封存與複製 |
| 12 | 設定安全 | 權限、備份、離線／錯誤處理、可存取性、資料保護、設定入口 |

## 必測情境
1. 首爾既有資料保留、重新整理及 Safari 重開不消失。
2. 建立曼谷／東京／台北等不同城市旅行，切換後天氣、時區、地圖不串資料。
3. 編輯跨日活動與轉乘事件，單日、週檢視、地圖一致。
4. 交通路線沒有可靠來源時，清楚標示未驗證；不得以計時器模擬實際到站。
5. 貼入 Google Maps 與 NAVER 地圖分享連結，對應平台正確開啟。
6. 多人各自勾選行李互不影響；離線、同步衝突可恢復。
7. 匯入重複旅行、壞檔案、空行程、錯誤日期不毀損原資料。
8. 逐項驗證按鈕、表單、資料保存、Safari 響應式版面及 GitHub Pages 實際部署。

## 交付門檻
每個功能需標記「實作完成／測試通過／受外部服務阻擋／未完成」；不得以語法檢查取代功能測試。必須能提出實際測試紀錄、部署版本及已知限制，才稱可驗收。
