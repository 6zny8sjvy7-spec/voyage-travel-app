## 已批准的介面與互動（未達者仍為阻擋交付項）
1. **首頁目的地＋天氣**：合併為不互相遮蓋的視覺區域。保留原本會輕微跳動的國家／城市代表性建築與圖示（使用者同意保留），不得用其他 SVG 直接取代或壓到天氣卡。韓、泰、日、越各國切換有對應地標；天氣隨實際來源顯示晴／雨／雪／夜，未取得不得偽裝真實天氣；日夜模式明顯不同但仍高質感、文字易讀。
2. **單日／週行事曆**：單日時間軸與週行事曆均呈現時間順序且保留比例、當天選取與視覺效果；旅遊天數可自行增加、不可強迫固定三天，不能誤刪既有日程。點一下景點／餐飲／活動定位至**當頁下方既有地圖**；點兩下開編輯；不要每張卡片再放重複的「編輯」按鈕。點擊在觸控裝置應有可理解且安全的操作方式，不應造成單點與雙點衝突。
3. **地圖**：既然單日行事曆已有內嵌地圖，移除底部重複的「獨立地圖頁」／導覽欄位；使用者可選 Google Maps／NAVER Map 外部導航，韓國地址用可查詢的韓文或正確名稱；只顯示有來源的路線／座標，不得用直線冒充導航。
4. **新增活動**：保留**單一**「＋安排活動（展開／收合）」入口，刪掉上方重複的「＋景點／＋餐飲／＋交通／＋購物」捷徑列；預設盡量收合，不讓整頁被新增表單佔據。內容依類別顯示真正必要欄位；依交通種類切換「步行／地鐵或 BTS／計程車或 Uber／公車／航班」對應欄位，不可只讓使用者手填時間與方向。
5. **航班／住宿**：在新增行程選到航班就能填**出發國家／機場、出發日期與當地時間、抵達國家／機場、抵達日期與當地時間、航班號**，保存後連動正確旅行日期；航班／住宿管理頁與日程須一致、不能有兩套互不相通欄位。當日期錯誤時要準確指出哪個日期、提供合理預設與明確修正方式；不得只說「時間不正確」。
6. **交通 A→B 查詢**：重點是精確的起終點、乘坐哪條線、**往哪個終點站／方向**、每段**搭幾站**與**中間所有站名**、正確轉乘。若 API 可可信取得 A 站相同路線、相同方向的下一班，才顯示幾分鐘進站（區分時刻表與即時），沒有則明確告知不支援。取消追蹤使用者上車、所在車站、下一站與列車背景 GPS；App 的手動目前位置地圖定位可以獨立保留。不可以把只有起終站的資料誤判 1 站，也不能把模擬 API 經過測試當成實際可用。
7. **行李**：備品可分類查找；個人勾選已打包時加刪除線但物品仍存在；單獨刪除模式不能與打包勾選混淆，資料跨重開保留。
8. **翻譯、幣別**：語言隨韓／泰／日／越切換，保留實用例句與翻譯工具；貨幣在旅行設定、開銷、換算選單用「國家／地區・貨幣名稱（ISO 代碼）」顯示，舊 ISO 資料鍵不變。
9. **AI 景點推薦**：使用者已正式要求移除，不得以別的名稱重新加入或保留佔位功能。不要擅自刪掉其他已批准功能。
10. **旅行資料**：切換國家／旅行前後資料保存，跨多趟旅行可回顧先前行程，保留匯出備份；若雲端同步無實際服務／帳號設定則標示未提供，不可宣稱已同步。

## 不能被舊 CI 綠燈掩蓋的檢查
- 對原 V2 與新版本的頁面截圖比對，確認跳動圖示與天氣不重疊、日夜清楚、沒有重複地圖頁／重複新增列／編輯按鈕。
- 實際操作新增並修改出發與抵達跨時區航班，同時驗證無效日期的準確提示及行程保存。
- 用真實公開資料測試韓／泰／日／越不同路線（至少各國指定案例）；地鐵站名／方向／站數與官方圖核對，有資料來源與時間；遇到來源無結果時不偽造。
- 行程單擊定位、雙擊編輯，分別測單日和週行事曆。
- 在桌面及模擬 iPhone WebKit 測試版面／無橫向溢出，最後使用實體 iPhone Safari 驗收。
- 未執行／未通過的測試寫明，**不准**用「78 項通過」取代以上需求驗收。
