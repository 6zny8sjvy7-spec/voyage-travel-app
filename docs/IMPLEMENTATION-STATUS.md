## 自動化測試

1. **Node**：`node --test tests/voyage.test.cjs`：CSV 引號、ICS、時區、衝突、費用分攤、日期、所有模組啟動、實際新增行程和費用。
2. **Browser**：`npm run test:e2e`：桌面 Chromium + **模擬 iPhone 13 的 WebKit**，對五頁籤、搭乘助手、記帳重開、分人打包、匯入不覆蓋、附近百科同意新增、雲端未設定提示、日記／購物清單、跨時區行程及出發倒數進行操作。
3. Github Actions：`.github/workflows/ci.yml` 在此分支及 PR 上執行。CI 若失敗，應修正並重新執行；**沒有綠燈不得宣稱已通過**。WebKit 模擬測試並不等於實體 iPhone Safari 測試。
4. 外部服務：Supabase 真實多人同步、官方車輛位置與獨立 AI 搜尋仍屬外部依賴，不得當作完成。

## 部署決策

原始 `main` 正式網站不受這次整合提交覆蓋。整合分支須經自動測試通過、確認需要的外部 API/帳號，並完成實際使用者驗收後才可進行正式切換。此報告不是最終交付完成證明。

## V6 需求變更與驗收門檻（2026-11-13，優先於上面舊版段落）

使用者已取消 **AI 景點推薦**、GPS 站點接近提醒、手動按「已上車／抵達下一站」和持續追蹤搭乘進度。上面歷史記錄中提及的「附近推薦」、「搭乘助手」和「GPS 前景追蹤」均為**已停用的舊需求**，不可再列為交付範圍。

### 現行交通規格

輸入 A 出發站和 B 抵達站後，一次搜尋應展示：
1. 出發站、抵達站、各路段搭乘路線／方向（headsign），轉乘站及全部可核實站名。
2. 只有資料源有**完整中間站清單**時，才列每段乘坐站數及整體站數。未取得完整資料時寫「站數尚未核實」，不可把只有 A 和 B 的資料錯算為搭乘一站。
3. 若來源有 A 站的下一班，且與查到的**同一路線、同方向**完全對上，才顯示距離發車／到站分鐘；明確區分來源標示的即時資料與時刻表資料。不可冒充連續倒數。
4. 韓國、泰國、日本、越南依國家／城市查詢，不得使用其他城市的站序，也不得拿地理上接近但站名不同的站替代。
5. 公開 API 沒有可靠資訊時，顯示缺資料和官方／外部導航入口。絕不偽造月台方向、站數、實時班次或車輛位置。
6. GPS 列車追蹤模組已刪除；地圖「我的位置」按鈕仍可依使用者主動授權在地圖定位，**與列車到站追蹤無關**。

### 行李

- 一般模式：勾選已打包物品，名稱出現刪除線，但不刪掉物品；保留每位旅伴獨立狀態。
- 刪除模式：隱藏分類選物清單和一般打包勾選框，只顯示刪除選取框，確認後才刪除。
- Chromium 與 WebKit 均需走完整加物、打勾、刪除模式、退出及持久化測試。

### 夜間視覺

- 晚上切換成真正的深靛藍／深海軍藍介面，白天保持亮色。
- 天氣區塊、卡片、表單、文字、下方導覽列同時轉為高對比深色，不可局部殘留刺眼白卡。
- Playwright 比較實際 DOM 計算的亮度，不接受白天和晚上幾乎同亮。

### 不可宣稱驗收完成的部分

- Transitous 交通來源的四國所有城市實際覆蓋與真實官方班次**尚未進行全面端到端驗證**；首爾官方即時到站資料尚需授權金鑰。
- 真正手機 Safari、四國當地查詢、實際列車資訊、斷線／弱網場景尚待實際測試。
- Supabase 雲端登入及多人同步依賴外部專案設定，尚未完成。
- **固定 V2 測試網頁仍是獨立版本**，不是自動同步 GitHub 開發分支；只有在整合版 QA 全通過並完成相同網址安全部署後，才可請使用者驗收。
- AI 景點推薦已從主要入口、開發分支及固定 V2 測試頁移除。
- 幣別選單統一顯示「國家／地區 · 貨幣中文名（代碼）」而保留原本 ISO 儲存值。

**發布準則：** 所有必須通過的自動化檢查為綠燈；與真實資料相關而尚未通過的需求須清楚標記，不以測試替身假裝完整；固定測試 URL 驗收後才考慮合併正式 main 根頁，絕不刪除原有旅行資料。
